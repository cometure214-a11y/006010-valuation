## 二、服务拓扑

```
GitHub 仓库（代码真源）
    │ git pull
    ▼
/opt/006010-valuation（git 工作区）
    │ 定时任务（cron）调用 scripts/*.py
    ▼
cache/*.json → docs/index.html → Nginx(80) → 公网页面
    │
    └── Server酱 → 微信推送（SendKey 在 cache/sckey.txt）
```

## 三、cron 定时任务

```bash
# 查看：crontab -l
0 9 * * 1-5   /opt/006010-valuation/run_daily.sh      # 盘前完整流程
10 15 * * 1-5 /opt/006010-valuation/run_daily.sh      # 收盘后更新
40 19 * * 1-5 /opt/006010-valuation/watch_evening.sh  # 晚间净值守望（每5分钟检测）
*/10 9-23 * * 1-5 health_check.py                     # 看门狗
30 20 * * 0   candidate_eval.py                       # 周日候选模型评测
```

**run_daily.sh 流程**（工作日 09:00 / 15:10）：
```
update_holdings（持仓自动更新）→ fetch_cloud（抓数据）
→ fund_holdings_infer（个股反推 P5）→ fund_valuation_v2（主估值）
→ gen_static（生成页面）→ daily_errors（误差日报）→ health_check（看门狗）
```

**watch_evening.sh 流程**（工作日 19:40 启动）：
```
每5分钟调 nav_watch.py --check 检测官方净值
→ 检测到更新（updated=1）→ 完整流程 + Server酱推送 → 退出
→ 23:50 未公布则本轮退出
```

## 五、微信推送（Server酱）

- SendKey 存于 `/opt/006010-valuation/cache/sckey.txt`（**不入库，注意安全**）
- 推送脚本：`scripts/notify.py`（完整估值）、`scripts/daily_errors.py`（误差日报）
- 测试：`./venv/bin/python scripts/notify.py "$(cat cache/sckey.txt)"`
- 接收：绑定 Server酱的微信账号（sct.ftqq.com）

## 六、日常运维

### 更新代码
```bash
cd /opt/006010-valuation && git pull origin main
# 如依赖变化：./venv/bin/pip install -r requirements.txt
```

### 手动跑一次完整流程
```bash
cd /opt/006010-valuation && ./run_daily.sh
tail -f /tmp/006010_daily.log
```

### 看当前估值结果
```bash
curl -s http://106.55.94.208/data.json | python3 -m json.tool
```

### 重启 Nginx
```bash
systemctl reload nginx   # 或 service nginx reload
```

### 常见故障排查
| 症状 | 排查 |
|------|------|
| 页面 502/404 | `systemctl status nginx`；检查 `/opt/006010-valuation/docs/index.html` 是否存在 |
| 页面数据过期 | 看 `/tmp/006010_daily.log` 是否有报错；手动跑 `run_daily.sh` |
| 晚间没推送 | 看 `/tmp/006010_watch.log`；确认 `cache/sckey.txt` 存在；当天净值是否已公布 |
| 微信收不到 | Server酱控制台查推送记录（sct.ftqq.com） |

## 七、安全注意

1. **sckey.txt 含推送密钥，勿提交 Git、勿外传**
2. 防火墙仅开放 22（SSH）和 80（HTTP），如需其他端口先确认再放行
3. 服务器 root 直连，建议定期 `apt update && apt upgrade`
4. 密钥轮换：如在 GitHub 泄漏 SendKey，立即到 Server酱重置
